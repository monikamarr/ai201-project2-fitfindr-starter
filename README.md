# FitFindr 👕🛍️

## Overview

FitFindr is a multi-tool AI shopping assistant that helps users discover secondhand clothing items and figure out how to style them using pieces they already own.

The system uses a planning loop to coordinate three tools:

1. `search_listings`
2. `suggest_outfit`
3. `create_fit_card`

The agent searches a secondhand clothing dataset, recommends a matching item, generates outfit suggestions, and creates a shareable social-media-style fit card.

---

# Tool Inventory

## Tool 1: `search_listings`

### Purpose

Searches the mock secondhand listings dataset and returns clothing items that match the user's request.

### Function Signature

```python
search_listings(
    description: str,
    size: str | None = None,
    max_price: float | None = None
) -> list[dict]
```

### Inputs

| Parameter   | Type         | Description                                                      |
| ----------- | ------------ | ---------------------------------------------------------------- |
| description | str          | Natural-language description of the clothing item the user wants |
| size        | str | None   | Requested clothing size. If None, size filtering is skipped      |
| max_price   | float | None | Maximum acceptable price. If None, price filtering is skipped    |

### Output

```python
list[dict]
```

Returns a list of listing dictionaries sorted by relevance.

Each listing contains:

```python
{
    "id": str,
    "title": str,
    "description": str,
    "category": str,
    "style_tags": list,
    "size": str,
    "condition": str,
    "price": float,
    "colors": list,
    "brand": str,
    "platform": str
}
```

---

## Tool 2: `suggest_outfit`

### Purpose

Generates outfit recommendations using a selected thrifted item and the user's wardrobe.

### Function Signature

```python
suggest_outfit(
    new_item: dict,
    wardrobe: dict
) -> str
```

### Inputs

| Parameter | Type | Description                                    |
| --------- | ---- | ---------------------------------------------- |
| new_item  | dict | Selected listing returned by `search_listings` |
| wardrobe  | dict | User wardrobe containing clothing items        |

### Output

```python
str
```

Returns one or more outfit recommendations generated by the Groq LLM.

Example:

```text
Pair the graphic tee with baggy jeans and chunky sneakers for a relaxed streetwear look.
```

---

## Tool 3: `create_fit_card`

### Purpose

Creates a short social-media-style caption based on the selected item and outfit recommendation.

### Function Signature

```python
create_fit_card(
    outfit: str,
    new_item: dict
) -> str
```

### Inputs

| Parameter | Type | Description                                        |
| --------- | ---- | -------------------------------------------------- |
| outfit    | str  | Outfit recommendation returned by `suggest_outfit` |
| new_item  | dict | Selected item returned by `search_listings`        |

### Output

```python
str
```

Returns a short fit-card caption.

Example:

```text
Just thrifted this Y2K baby tee and paired it with baggy jeans and chunky sneakers. Easy streetwear fit for everyday wear.
```

# Planning Loop

The agent uses a conditional planning loop.

First, the user submits a natural-language query.

The agent parses the query and extracts:

* description
* size
* max_price

The agent then calls:

```python
search_listings()
```

If no listings are found:

1. The agent stores an error message.
2. The planning loop stops immediately.
3. `suggest_outfit()` is not called.
4. `create_fit_card()` is not called.

If listings are found:

1. The highest-ranked result becomes `selected_item`.
2. The agent calls `suggest_outfit(selected_item, wardrobe)`.
3. The generated outfit is stored.
4. The agent calls `create_fit_card(outfit, selected_item)`.
5. The completed session is returned.

The planning loop therefore changes behavior depending on the result of the search tool instead of always calling all three tools.

---

# State Management

The project uses a session dictionary to store information during a user interaction.

Example:

```python
session = {
    "query": query,
    "parsed": {},
    "search_results": [],
    "selected_item": None,
    "wardrobe": wardrobe,
    "outfit_suggestion": None,
    "fit_card": None,
    "error": None
}
```

### State Flow

After query parsing:

```python
session["parsed"]
```

stores:

```python
{
    "description": "...",
    "size": "...",
    "max_price": ...
}
```

After searching:

```python
session["search_results"]
session["selected_item"]
```

are populated.

The selected item is passed directly into:

```python
suggest_outfit(selected_item, wardrobe)
```

The resulting outfit is stored:

```python
session["outfit_suggestion"]
```

and passed directly into:

```python
create_fit_card(outfit_suggestion, selected_item)
```

The final caption is stored as:

```python
session["fit_card"]
```

Data flows through the agent as:

```text
User Query
→ Parsed Parameters
→ Search Results
→ Selected Item
→ Outfit Suggestion
→ Fit Card
```

The user never has to re-enter information between tools.

# Error Handling

## Tool 1: search_listings

### Failure Mode

No listings match the user's query.

### Agent Response

The tool returns an empty list.

The planning loop stores:

```python
session["error"]
```

and immediately stops execution.

### Example

Input:

```text
designer ballgown size XXS under $5
```

Output:

```text
I couldn't find any matching listings. Try a broader description, a higher budget, or a different size.
```

---

## Tool 2: suggest_outfit

### Failure Mode

The user's wardrobe is empty.

### Agent Response

The tool does not fail.

Instead, it generates general styling advice without using wardrobe items.

### Example

Input:

```python
get_empty_wardrobe()
```

Output:

The LLM generated styling recommendations using common clothing pieces rather than specific wardrobe items.

---

## Tool 3: create_fit_card

### Failure Mode

The outfit suggestion is missing or empty.

### Agent Response

The tool returns a descriptive error message instead of calling the LLM.

### Example

Input:

```python
create_fit_card("", sample_item)
```

Output:

```text
I need an outfit suggestion before I can create a fit card.
```

# Spec Reflection

One way the specification helped was by forcing the planning loop and state-management design to be completed before implementation. This made it easier to build and test each tool independently before connecting them together.

One way the implementation diverged from the original specification was query parsing. During planning, I considered using an LLM to extract structured fields from the user's query. During implementation, I used regular expressions instead because they were faster, easier to test, and more reliable for extracting sizes and prices from predictable queries.

Another small change was the ranking strategy used in `search_listings()`. Instead of only filtering results, the final implementation uses keyword-overlap scoring to rank listings by relevance.
